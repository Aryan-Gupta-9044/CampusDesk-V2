# FRESH V2 DATABASE ONLY — DO NOT RUN ON AN EXISTING CAMPUSDESK V1 DATABASE  (Option B)

For a **new, empty Supabase project** (demo, staging, or the future V2 production project).

Run in this order in the SQL Editor:

1. `schema.sql`      – tables, constraints, indexes
2. `functions.sql`   – helpers, fee / report / results / attendance functions
3. `triggers.sql`    – payment guard, notifications, signup + role-lock hardening
4. `rls.sql`         – Row Level Security for every table
5. `storage.sql`     – `avatars` (public), `documents` + `receipts` (private) buckets and policies
6. `seed.sql`        – demo data (**aborts on a database that has real accounts**)

`reset_demo_data.sql` removes only the `@campusdesk.com` demo rows so `seed.sql` can be run again (also fresh-only, also guarded).

`schema/functions/triggers/rls/storage.sql` are generated by `python3 scripts/build-fresh.py` from `../migrations`. `_base_tables.sql`, `_rls_base.sql`, `_storage_base.sql` are the hand-written sources.

Demo logins are in the repository README.
